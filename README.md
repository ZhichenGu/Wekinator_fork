# 摄像头动作学习 / Motion Studio

本机运行的中文摄像头动作学习 demo。使用 React、TypeScript、MediaPipe Tasks Vision；无 OSC，无云端 API，无视频上传。

## 启动

需要 Node.js 22.12 或更高兼容版本。

```sh
npm install --registry=https://registry.npmjs.org
npm run dev
```

打开终端显示的 localhost 地址。摄像头必须在 localhost 或 HTTPS 下使用。构建生产文件：`npm run build`，算法测试：`npm test`。

## 使用

1. 新建项目，选择手部、面部或身体追踪。
2. 点击开启摄像头，允许本地摄像头访问。
3. 创建动作，选择“形变 + 整体轨迹”等特征，录制完整示例；默认三秒倒计时、三秒录制。
4. 可拖动骨骼回放检查示例，录制不同位置的正例和容易混淆的负例。
5. 点击训练动作，再开始运行。完成相近动作后，触发扩散动画或切换效果画面。
6. 动作退出并复位后才能再次触发。根据测试调整阈值，重新录制或修改特征后需要训练。

项目自动保存到当前浏览器 IndexedDB，也可导出 JSON 并重新打开。清除浏览器数据会删除本地保存，请按需导出备份。只保存关键点与特征，不保存原始视频。

## 已实现的边界

- 三种检测方式每个项目选一种；单人、单只手，不融合多模态。
- 使用相对坐标与尺度归一化，默认保留动作方向；Z 暂不参与匹配。
- 使用模板与带约束 DTW、多时长窗口、起终点与运动量检查、负例排除、竞争动作区分和复位状态机。
- 模板构建不等于神经网络训练；默认阈值没有经过真实用户数据校准，分数不是概率。
- 模型在本地 public/models，WASM 在本地 public/wasm。模型下载自 Google 官方 MediaPipe 模型存储，依赖锁定于 package-lock.json。
- 优先尝试 Worker 推理；模块 Worker 不兼容时降级为限频主线程推理，画面显示“兼容模式”。CPU 推理速度取决于机器。时序匹配当前在主线程，不声称已达到固定性能目标。
- 姿态分类、连续数值控制、双手、多人、GPT API、物体框选、颜色追踪、原始视频回放和 Mac 封装尚未实现。
- 当前只能测试应用内效果，不执行其他软件或系统命令。

## 手动验收

真实摄像头依次检查：左中右位置重复同一动作、近远变化、稍快稍慢、只做前半段、保持终点、倒序、追踪丢失、一次触发和复位后再触发。面部/身体至少各测试一个动态动作。记录设备、帧率、误触发、漏检与动作结束后的延迟。合成算法测试不能替代这些真实摄像头检查。

本项目为本地开发 demo，没有部署外网，也不是已经构建完成的 Mac app。

界面约定：黑白灰，无宣传口号、装饰文案或营销式首页。首页直接提供项目操作，说明只服务于操作、模型用途和状态判断。

开发环境可打开 `/diagnostics.html`，点击“运行模型测试”验证本地模型加载与空白帧推理；它不调用摄像头，也不能证明真实动作识别质量。
