# 手部六种交互复查

日期：2026-11-14；现有预览副本 0.90。未合回正式仓库、推送、部署或重打桌面包。

## 结束在途检测修复 0.94

录制结束瞬间仍有检测在途的竞态已修复。手动/自动结束共用冻结截止时间、停止新检测和最长 350 ms 等待；末帧先做身份检查，超时/丢失取消，结束时刻之后的帧不进入示范。原结束时间用于质量判断，重复保存不延长等待。

受控浏览器已走过手动/自动两种路径，各自确认同手延迟可保存、换手延迟取消。额外 900 ms 检测迟到时未新增录制，返回后计数也保持不变。这替代 0.93 中“结束竞争时序待验证”的条目。真人高可信错标签限制继续存在。

## 独立检查 0.93

- 已纠正公共选手器测试伪装为五种模式覆盖的问题。新增实际动态完整动作得到一次事件，两只手各做一半得到零次事件。姿态测试经过 Recognizer，区域与捏合经过实际几何计算后进入门控，连续经过回归控制器。
- 接替边界在丢失后 299 ms 暂停、300 ms 接替；当前手存在时另一手入镜不抢占。未增加全局等待时间。
- 可观察的高可信标签突然互换、交叉重叠和重复标签现在传出运行期身份歧议信号，录制立即取消。浏览器确认原有训练示范保留。
- 追踪保存立即排队，防止快速切换项目清掉旧定时保存，并防止旧写入结果错误更新新项目状态。实际录制独立测试后切到另一项目、刷新再打开，训练与测试分别为 left/right，各 45 帧，用途保留。已直接读取 IndexedDB 并做 JSON 校验，下载文件本轮未完成独立检查。
- 合成反例显示，物理 A/B 不同但模型输入完全相同且标签相同，保护无法识别身份更换。这是未解决限制。单靠当前关键点与手别无法消除，不能报告为身份验证通过。
- 本轮模拟 Worker 使用实际 init.stableHand 决定是否启用生产选手器；去掉该入口标志会退回数组第一手，双手入镜检查应失败。主线程兼容路径通过源码核对使用相同选手器和歧义信号，未在本轮强制运行真实 WASM 回退。
- Serial/MQTT 验证范围为现有编码/模拟发送回归，OSC 现有回归到本机独立 UDP 收包。没有物理接收设备或真实 Broker。本轮没有逐一将五种事件发送至外部软件。
- 仓库中仅有 MQTT 教程视频，未发现可用于真实手部检测验收的录像。手部强遮挡模型准确率仍待验。录制结束前最后一次检测尚未返回的竞争时序，本轮未完成专门验证。

## 遮挡恢复复查 0.92

手部丢失现在暂停识别门控，不用缺失帧作为解除条件；同姿态遮挡返回不重复触发，动态片段不跨空帧拼接。真实未知姿态和已观察到的退出仍按原规则解除。新旧单手项目均覆盖。233 项回归与构建通过。

受控工作台复查：第二只手不抢控制；换手录制取消；同手录制正常保存，刷新重开保留唯一完整示范。姿态/动态/连续/规则门控使用生产类合成序列验证，并非五种真人准确率验收。

## 后续修复 0.91

用户授权后，前五种交互也已接入稳定选手保护。Worker 和主线程均检测两手、只交付当前一手；当前手有效时不抢占，丢失先暂停，持续约 300 ms 后允许接替。录制期间检测到换手即取消，不保存混合示范；导入/保存校验也拒绝新带手别数据中的混合录制。旧不带手别录制继续兼容。

228 项回归与构建通过。受控浏览器实测正常工作台第二手入镜不抢占、换手录制取消。以下 0.90 关于缺少稳定选手的条目属于历史检查结果，已被本节替代；真人强遮挡下标签误判仍需实测。

## 结论（0.90 历史检查）

今天坐标输出的单双手、身份稳定与自动接替改动没有接入前五种新项目的学习/规则路径。前五种仍检测一只手；只有坐标输出请求两手并调用 CoordinateHands。旧双手/混合学习项目继续保留、导出，不开放运行。

本次修复共用 PointPicker 在长按 Enter/空格时反复选择或移除同一点的问题，同时忽略组合键和输入法组合确认。未修改识别阈值、算法、录制内容或输出协议。

| --- | --- |

| 区域停留 | 选中点使用镜像坐标；停留计时；缺失中断；需确认离开才重新触发；选点和小数时长保存 |

共用检查：Skeleton 与 PointPicker 使用一致的镜像坐标；区域一个点、关系两个点、学习关注点和直接输出点分别存储。改变学习关注点会重新计算特征并使训练失效，保留原始录制。创建菜单只有坐标提供单双手；坐标配置不进入其他五种项目的新建数据。相关测试位于 focus、core、learning、continuous、region、PointPicker、hand-learning-ui、coordinate-* 等测试文件。

## 实际验证与限制

- 196 项前端/算法/案例测试及 30 项服务端测试通过；TypeScript 与生产构建通过。
- 本轮浏览器使用真实共用选点组件：Enter 一次、长按 Enter 900 ms 共执行两次；Ctrl+Enter 不增加次数；再长按空格 900 ms 只增加一次。临时页面已移除。
- 前一轮 0.89 的真实坐标工作台受控摄像流检查仍有效：创建、换手、双手入镜、重叠暂停与恢复、21 点保存重开。该测试使用生产选手器，但不是真人 MediaPipe 准确率实验。
- 本轮没有逐个模式用真人录制训练，没有物理串口、真实 Broker 或创作软件的硬件验收。不能将算法回归等同于现场识别准确率。
- 原有单手学习/规则检测不提供坐标输出的稳定选手保证。双手同时入镜时检测器可能切换目标；录制/使用这五种单手交互时应让一只手清晰入镜。尤其不要把一次录制中的换手当作已经受到身份检测保护。若未来统一该能力，应单独检查录制身份、特征清空与门控恢复，不能直接套用双手坐标配置。
