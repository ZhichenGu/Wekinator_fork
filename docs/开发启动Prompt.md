# 开发启动 Prompt

将本文件与《产品与技术规格.md》一起交给开发代理。以下是执行任务，不只是讨论方案。

---

请实现一个中文的摄像头交互学习应用。先交付真实可运行的浏览器 demo，架构允许以后复用为 Mac Electron app。严格参考随附《产品与技术规格.md》；这份规格标注的未来能力，不要擅自当成本轮全部实现要求。

## 产品核心

用户创建项目，选择手部、面部或身体检测，录制几条动作示范，训练动作，再让摄像头持续判断是否完成相近动作，匹配后执行应用内效果。

最重要案例：录制约三秒手指动作，在画面另一处重复它，也能在完整动作结束后触发 A。识别依据是相对形变和动作轨迹随时间的变化，不是固定像素位置或最终姿态。

不使用 OSC，不创建 OSC 设置、端口配置或消息地址。

## 实施顺序

1. 检查现有仓库、运行环境与适用指令；复用可用基础。
2. 使用 TypeScript + React + Vite，接入 MediaPipe Tasks Vision。先跑通手部的真实检测与数据录制，再实现完整动作匹配与效果。
3. 完成项目创建、录制/骨骼回放、训练、运行、停止与本地保存的端到端闭环。
4. 再增加面部、身体各自的检测和动态动作工作流。每个项目首版只启用一个检测源。
5. 为桌面封装保留平台适配层；若本轮明确要求 Mac 交付，则继续完成 Electron 构建与当前机器实测，否则在交付中明确桌面封装尚未执行。

## 界面要求

全中文，黑白灰界面，不使用绿色主题。它是实际操作工具，不制作营销首页；删去宣传口号、装饰文案、情绪化标题和品牌式页脚。首页直接提供新建、打开和最近项目。保留必要操作说明、状态和错误提示。新建项目用卡片介绍“手部追踪、面部追踪、身体追踪”的作用。

把“检测方式”与“学习方式”分开：动态动作匹配为可用核心；姿态分类、连续控制未实现时显示规划中并禁止进入。不要把三种检测器说成三种训练算法。

工作台包括动作列表、摄像头与骨骼叠加、示例管理、效果设置以及清晰的录制—训练—运行按钮。状态包含权限失败、加载失败、追踪丢失、样本不足、待训练、正在运行、等待复位。

首版效果至少支持切换应用内场景和播放内置动画，另有手动测试按钮与触发日志。视觉应像可用的创意工具，不只是一张展示页。

## 算法要求

- 检测器使用预训练模型；用户示范训练的是动作模板，不重新训练骨骼网络。
- 默认平移与尺度归一化，保留方向；形变与整体移动轨迹独立处理，避免移除画圈信息。
- 时间戳采样、重采样、平滑、缺失数据处理与特征版本必须明确。
- 可从受约束 DTW + 有限多时长后缀窗口开始；完整模板覆盖、合理时长、运动量和终点检查是必要条件。
- 同一完整动作只触发一次，退出/复位后才能再次触发，不能只靠固定冷却时间。
- 只完成前半段、静止停在终点、反向动作、检测丢失不能误当完整成功。
- 匹配分数不是概率。阈值用留出正例和负例调整；不足时坦诚显示未充分校准。
- 优先在 Worker 中推理与匹配，限制在途视频帧，不积压过时帧。
- 模型与依赖锁定兼容版本，资源加载失败显示明确错误；桌面阶段打包离线资源。

## 扩展边界

用轻量类型与适配层预留物体检测框、标签和 GPT 视觉语义结果，不搭建通用插件平台。首版不接入云端 API、不索要 API key、不上传视频。

未来检测器负责框与位置，GPT 负责语义补充；异步 API 不进入逐帧动作匹配的关键路径。密钥不能进入前端包或导出项目。

## 验证与交付

对真正重要的时序行为做测试：位置与尺度变化、不同速度、完整/局部/倒序动作、缺帧、重复触发与复位。实测摄像头权限、保存后打开、停止后释放摄像头、中文界面与按钮状态。

报告实际测试设备、测试方式与结果。没有摄像头访问或其他环境条件时，继续完成独立部分，明确哪些仅做了录制数据测试、哪些尚未真实摄像头验证；不得用合成样本结果冒充真实识别效果。

最终提供启动命令、可访问的 demo、实现范围、实际验证与已知限制。若交付 Mac app，提供真实构建路径并说明架构、签名与公证状态。不要把网页、构建脚本或界面截图称为已经完成的 Mac app。
