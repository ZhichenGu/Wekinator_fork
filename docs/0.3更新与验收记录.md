## 本轮交付

### 网站访问密码

整个网站先验证访问密码，默认按用户要求为 `0000`。由 Node 服务校验，不是前端的隐藏开关。应用脚本、WASM、模型、案例下载均经过同一验证。错误密码不会进入工作台，失败次数有限制。

会话使用 HttpOnly、SameSite=Strict 的签名 Cookie，默认 12 小时；右上角“退出”会清除 Cookie 并在当前服务中撤销会话。默认签名密钥由服务随机生成，重启后需要重新输入密码；可以通过服务器环境变量 `APP_PASSWORD`、`SESSION_SECRET` 配置。HTTPS 部署时设置 `AUTH_COOKIE_SECURE=true`。

这是共享密码访问，不是多用户账户与角色系统。项目数据仍在各浏览器本地。密码保护依赖 Node 服务；直接将 dist 上传到 GitHub Pages 等纯静态托管，不会运行这套服务端验证。

### 姿态分类

新建项目可选择“动态动作匹配”或“姿态分类”，检测输入仍可选手部、面部、身体。旧项目默认保留动态模式，不强制迁移数据到分类模式。

姿态分类使用每次稳定录制的相对形状特征中位数作为原型，比较当前短窗口与训练原型的距离。它不要求姿态发生运动，也不把整只手在画面中的绝对位置作为类别。

- 变化过大或追踪不连续的姿态训练示例不采用。
- 低于阈值、负例更接近或多个类别难以区分时，显示未知/不确定并不触发。
- “稳定确认”支持 0.10–3.00 秒、两位小数，默认 0.35 秒。
- 同一种姿态持续保持只触发一次；稳定切换到另一类别可以再次触发。持续离开已知姿态后可复位。
- 仍复用状态灯、Serial、MQTT。分类确认的绿灯不等同于外部设备已执行。

这是一种模板/原型分类方法，不是重新训练骨骼网络。真实识别质量需要用户的实际录制验证。

### 独立测试

录制用途分为“训练示例”和“独立测试”。测试录制不进入模型；追加测试录制不使已训练模型失效，修改训练数据或调整录制归属则需要重新训练。调整设置后，已有测试报告会清除，避免显示旧参数的结论。

“独立测试”标签页在后台 Worker 中重放测试数据，使用与实时运行相同的识别器及触发规则。该流程不调用 Serial/MQTT 输出，即使未连接设备也能测试。

报告包括正例一次正确触发数/有效测试数、负例保持无触发数、漏检、类别混淆、重复触发、负例误触发次数和观察时长、各类别结果，以及逐条触发时刻。混淆表显示每条录制的首次触发，完整事件列在逐条结果中。

与训练数据相同的测试录制会剔除，重复测试也不重复计入。所有分母为零的项目显示“未测试”，不虚构准确率。可以导出带项目名称的 JSON 报告。时间从测试片段开始计，不冒充“动作完成后的延迟”。

### 两种案例下载

Serial 与 MQTT 区域都提供同排按钮：左侧“测试发送”，右侧“案例代码下载”。下载不依赖设备已连接，但需要通过网站访问验证。

- `serial_success_led.ino`：保留用户提供的程序，串口 115200，接收 `/success` 与 LF，亮灯后 3 秒熄灭。
- `esp32s3_mqtt_led.ino`：默认 ESP32-S3、Arduino-ESP32 3.x；在文件顶部填写 Wi-Fi、Broker、TCP/TLS 端口、认证、Topic 和触发内容。默认 Topic `project/action`、触发消息 `YES`，收到后 RGB 灯亮绿灯，3 秒后熄灭。

MQTT 例程需安装 PubSubClient。网页使用 WebSocket URL；板子连接同一个 Broker 的 TCP/TLS 入口，不能照抄网页的 WebSocket 端口或 `/mqtt` 路径。TLS 通过 `MQTT_USE_TLS` 开启，并填写对应根证书，未使用跳过证书验证的方式。

RGB 灯优先采用所选板型的 `RGB_BUILTIN`。若板型未定义，示例回退 GPIO48；可通过 `CUSTOM_RGB_LED_PIN` 修改。ESP32-S3-DevKitC-1 的 v1.0 与 v1.1 灯脚不同，v1.1 为 GPIO38，应按实际板卡配置。

固件未在本环境进行 ESP32 工具链编译或真机烧录。已验证下载成功、文件字节一致，并核对主要 API 的官方示例。网络异常、硬件版本和实际灯控时序仍需板上测试。

## 使用顺序

1. 打开网站，输入 `0000`。
2. 新建项目，选择检测方式与“姿态分类”。
3. 录制用途选训练示例，保持一种姿态，录几次后训练；不同类别分别录制。
4. 改为独立测试，为各类别重新录制；负例勾选“本次不应触发任何动作”。
5. 运行独立测试，检查误触发、漏检和混淆，再决定补录哪些示例或调整阈值。
6. 正式运行时连接 Serial 或 MQTT。需要硬件案例时，从右侧按钮下载 .ino 后填写相应配置。
