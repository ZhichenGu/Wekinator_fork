# 预览版 0.4：身体追踪预览修复

2026-11-04。仓库：`/Users/zhichengu/Documents/GitHub/Wekinator_fork`。

## 原因与处理

身体模型已完整保存在本地，文件大小 5,777,746 字节；ZIP 目录与成员 CRC 校验通过。浏览器加载、CPU 初始化和空白帧推理通过。

发现预览与训练共用 `extract()` 结果：肩、髋、手腕、膝盖和脚踝中任一所需关节 visibility 低于 0.45，训练特征被拒绝，同时整个预览骨骼被清空。这会使半身画面看起来像模型未加载。

0.4 将原始检测关节与可训练帧分开传递，Worker 和兼容模式都更新。可见关节用于预览；仅当一条骨骼两端均可信时绘制连接，不跨过缺失关节连线。身体不完整时显示提示，训练和触发继续使用完整身体的原有门槛，不把低可信的补全关节当成训练数据。

摄像头状态区区分“模型已就绪 · 等待目标”、“身体已检测 · 全身不完整”和“追踪中”。骨骼示例回放同步使用更新后的绘制组件。版号、package/lock 与初始加载文字同步至 0.4。

## 实际验证

- 36 项前端/算法/输出测试和 2 项访问验证测试，共 38 项通过；其中新增 2 项覆盖部分身体可预览但不可训练、缺失中间关节不产生错误连接。
- TypeScript 检查和 Vite 构建通过。
- 使用 MediaPipe 官方公开测试图片，由本地身体模型进行真实推理：全身与裁切半身画面均返回 33 个关节。
- 全身画面通过原有训练门槛，显示 33 个关节、12 条连接；裁切半身画面未通过训练门槛，仍显示 23 个可信关节、5 条连接。截图已检查。
- 临时回归页面和测试图已从仓库移除，验证副本保存在本轮 work/body-fix 中。

未使用用户摄像头，也未验证用户所处环境的光线、距离或摄像头硬件。该修复解决已复现的“部分身体被检测但预览全空”问题，用户刷新到 0.4 后还需在实际摄像头画面确认。

## 使用

刷新 `http://127.0.0.1:5173/`，确认右上角显示预览版 0.4。新建项目时选择“身体追踪”；旧手部项目的输入类型不会自动变更。进入工作台开启摄像头，半身入镜可预览，但录制全身动作时仍需要后退，让所需关节清晰入镜。

测试图片来源：[MediaPipe 官方公开姿态图片](https://storage.googleapis.com/mediapipe-assets/pose.jpg)。
