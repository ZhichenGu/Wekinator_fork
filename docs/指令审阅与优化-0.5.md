|---|---|---|

| 澄清、批准、预览缺少明确的依赖边界 | 每一步询问，等待影响所有工作 | 只等待必须答案的部分；已授权可逆工作继续，预览不成为关卡 |

| 所有任务都强调完整验证，但未写清 API/硬件缺席如何处理 | 无 Key 就无法完成任何独立部分，或把模拟当联调 | 明确模拟继续、真实联调单列，不编造凭证或真实效果 |
| 模型名称偏好可能被理解为必须切换模型、扩大架构或多代理 | 不必要分工、工具调用与过度工程 | 明确本文件不改变实际模型；高能力模型优先自主判断与最小可靠方案 |

## 实际读取的 Skills 与建议

### OpenAI Docs

来源：`/Users/zhichengu/.codex/skills/.system/openai-docs/SKILL.md`。

“First substantive action”要求在本地代码检查前先查官方文档，与一般开发的先看仓库流程存在顺序张力。建议上游按任务限定：API 概念/接口先查官方资料；与 API 无关的 Git 状态、适用指令和安全只读检查不应被视为违反顺序。本轮已核对官方图片输入与结构化输出说明。

“Before building…use openai-platform-api-key first when available”有合理的 available 条件。建议增加：工具不可用或用户自带 Key 产品无开发者凭证时，继续实现和模拟测试，不要求用户把真实 Key 发到聊天。本轮无该工具，也未使用真实 Key。
