# 当前摄像头交互与 MQTT 检查

2026-11-09 · 预览版 0.43。历史规格保留作开发记录，当前使用方式以 README 和这里为准。

## 摄像头工作台

- 手、脸、身体共用紧凑布局。动态动作、姿态分类、连续控制的录制设置在左侧动作列表上方；录制操作留在画面下方。
- 区域停留选一个点，动作关系选两个点，直接设置规则，不出现录制训练设置。
- 动作名可双击、按 F2，或点击铅笔重命名。输入中 Enter 保存，Esc 取消。
- 关注部位、学习方式默认展开，可以折叠。悬停详情等 0.8 秒出现。
- 摄像头画面向上滚出约 65% 时出现小预览；返回一半时收起。可拖动，复用现有视频，不请求第二路摄像头。
- 小预览使用对应手、脸、身体骨骼及原来的镜像方向；视觉 API 显示原画面与识别状态，不叠加骨骼、不加入训练步骤。
- 连续控制显示当前数值；其他模式显示识别或触发状态。不能据此认定设备已执行。

## MQTT：教程和实现是否对应

| 教程步骤 | 代码行为与检查 |
| --- | --- |
| 填 WebSocket URL、独立用户名密码 | 网页接收 ws / wss；HTTPS 页面要求 wss；URL 不允许嵌入凭证 |
| 保存，再连接 | 未保存修改会阻止测试和运行；保存不会自动连接 |
| Topic 和内容与设备一致 | 点灯案例默认 project/action + YES；连续控制下载数值接收案例，未设置消息时默认模板 {value} |
| 测试后接识别 | 动作触发提交动作消息；视觉与声音按确认后的结果变化发送；连续控制按限速策略发送数值 |
| QoS 0 / 1 | QoS 0 仅提交发送；QoS 1 等 Broker 确认；都不证明设备执行 |
| 断线不补发 | 不自动重连；连接断开时发送被拒绝；retain=false |
| ESP32 连接同一个 Broker | 网页用 WSS，设备用 TCP/TLS。云端设备示例需开启 TLS 并填写根证书 |

本次修复：连续控制的案例下载从点灯程序改为数值接收程序；连接失败后忽略迟到的 connect 事件，避免状态误恢复。

## 实际验证与边界

- TypeScript 与生产构建通过。自动检查覆盖布局组件、重命名入口、三类选点、翻译、时序匹配、输出及服务端权限。
- 实际运行 MQTT.js 发布端和独立 MQTT.js 订阅端，中间使用本机 WebSocket 协议测试服务。确认 project/action 收到 YES 和 0.375、QoS 1 PUBACK、retain=false、断线后拒发。它不是生产 Broker 的验收。
- 浏览器自动访问 localhost 被保存的权限设置阻止，本次未操作页面验证拖动、折叠、真实摄像头或浏览器 WSS。组件测试和构建不能替代这些实测。
- 没有连接用户的公网 Broker；没有编译、烧录或实测 ESP32。实际主机、认证、ACL、根证书和板卡仍需现场核对。

## 核对的官方资料

- [MQTT.js](https://github.com/mqttjs/MQTT.js)：浏览器 WebSocket、reconnectPeriod、queueQoSZero 与发布选项。
- [EMQX Serverless 官方说明](https://docs.emqx.com/en/cloud/latest/create/serverless.html)：默认 WSS 8084、MQTT TLS 8883；默认 Spend Limit=0 只使用免费额度。实际端口和路径以自己的部署为准。
