# AGENTS.md 与相关 Skills 审阅

范围：用户在对话中提供的 AGENTS.md、当前可见的 Skill 说明，以及本任务实际读取的 Sites、OpenAI Docs 指令。未逐一加载无关 Skill，也未修改插件或系统文件。本审阅不能改变上级规则或实际运行模型。

## 结论

原 AGENTS.md 的自主性、澄清和批准约定已经比较清楚。主要问题是缺少新增需求的承接规则、对 Skill 工作流与用户范围的冲突处理，以及“完成”的验证证据分级。建议保持简短的通用约定，把艺术作品集规则与当前软件开发规则分开，避免无关规则进入每个任务。

## 具体调整

| 位置 | 可能导致的问题 | 优化 |
| --- | --- | --- |
| 标题“面向 GPT-6 Astra” | 与用户现在提到的 GPT-6.1 不一致，也容易被误解为能在指令中切换运行模型 | 改为模型无关的协作约定；实际模型由产品/运行环境选择 |
| “Skills 只加载直接相关部分” | 可能与上级强制触发、工具调用前必须读取的要求冲突 | 补充“遵守上级强制要求，其他内容按需读取” |
| 已授权范围内自主推进 | 没说明用户中途补充内容怎样处理，可能漏掉审阅、布局等新增要求 | 补充后续消息默认承接任务，明确记录新增范围与分阶段交付 |
| 审美反馈与批准 | 工具流程可能把预览当等待许可的节点，造成反复确认 | 明确预览不自动阻断已授权工作，必要批准指向具体操作 |
| “完成与验证” | 容易将“有 demo”理解为静态界面或模拟效果 | 明确真实行为、构建检查、合成数据测试的证据不可互换 |
| 失败处理 | “先诊断再修正”很好，但缺少未知写入状态的优先查询 | 保留并明确外部写入不盲目重试 |
| 艺术作品集专用规则 | 对软件工程无关，容易造成额外设计体系或 Figma 产物 | 保留为其他项目的专用规则；当前仓库 AGENTS 只保留软件约定 |
| Sites 默认完成后发布 | 本项目当前阶段是本地 demo，用户未要求外网发布 | 当前仓库明确本地开发范围；将来明确要求托管再按 Sites 发布工作流处理 |
| Sites 默认简单项目 buildless | 当前目标含 TypeScript 时序算法、测试和后续桌面复用，机械采用 buildless 会妨碍维护 | 采用已有规格的 React / TypeScript / Vite，避免不必要服务器和托管 |
| 多个 Figma Skills 触发条件重叠 | 同一复合任务可能叠加多个流程与设计系统产物 | 本任务没有 Figma 请求，不触发；未来先定交付方向，再加载对应强制 Skill，不把 Skill 名单当任务列表 |
| OpenAI Docs | 对未来 GPT 扩展应核实能力，但不应把阅读文档升级为立刻接 API 或索要密钥 | 仅核对未来架构相关文档；首版不接 API、不需要密钥 |

## 给高能力模型的工作空间

优化重点是清楚描述目标、边界和完成证据，把可逆实现细节留给模型判断。不要用固定工具次数、固定流程页数、每步批准或无条件“永不停止”代替判断力。局部受阻需要诚实交付状态，而不是伪造完成或无限循环。
